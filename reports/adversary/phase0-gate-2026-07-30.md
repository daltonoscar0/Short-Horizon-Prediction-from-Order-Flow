VERDICT: SURVIVED WITH CAVEATS

Phase-0 gate synthesis, 2026-07-30. Inputs: three verification agents and three adversary
passes (`phase0-alignment`, `phase0-parser`, `phase0-quality`), each run independently of the others.
No pass returned KILLED. Every blocker/major finding below was re-verified in this session
against the real code and data; findings I could not reproduce are listed as refuted.

Bottom line: **the alignment convention is correct and the committed numbers are correct.**
What survives is a class of *evidence* defects — the committed record (`DECISIONS.md`,
`docs/DATA_CONTRACT.md`, `reports/data_quality.md`) claims stronger verification than the
shipped code performs, and the one gate that would catch the phase's designated
highest-risk bug is the one that silently skips on a fresh clone. Phase 1 may proceed;
these are documentation- and test-strength debts, not numeric errors.

Positive result worth recording: the vendor spec text was retrieved this session and it
confirms the convention verbatim. `curl -sSL "https://web.archive.org/web/2023/https://lobsterdata.com/info/DataStructure.php"`
returns HTTP 200 / 30,949 bytes (snapshot 20240427184519) containing:

> "The k-th row in the 'message' file describes the limit order event causing the change in
> the limit order book from line k-1 to line k in the 'orderbook' file."

That is the primary-source confirmation Phase 0 recorded as unobtainable.

## CONFIRMED findings, ranked

### 1. MAJOR — `make data` cannot detect message/orderbook misalignment at all
`src/edge/io/quality.py:329` (`hard_failures`)

All three hard gates (crossed-book, row-count equality, ts monotonicity) are properties of
the message file and the orderbook file *considered separately*. None constrains the join.

Reproduced: copied the AMZN raw pair to `/tmp`, dropped the orderbook file's first row and
duplicated its last (same 269,748 rows, every row off by one event), ran the real
`edge.io.lobster` then `edge.io.quality`:

```
AMZN: crossed=0 monotonic=True u_shape=True median_mid=$222.6550 (bounds ok=True)
lobster_exit=0  quality_exit=0
```

`make data` passes and writes a report whose every PASS field is identical to the committed
one. For contrast, `tests/test_alignment.py` against the same shifted copy fails with
`33 != 500`. So `make test` catches it, `make data` cannot, and `make test` is not a
prerequisite of `make data`.

### 2. MAJOR — the alignment invariant skips silently on a fresh checkout
`tests/test_alignment.py:68`

`data/` is gitignored, so `_raw_files_present()` is False on any clone. Reproduced:
`git clone /Users/oscardalton/edge /tmp/gate/clone && make test` →
`Ran 28 tests in 0.461s / OK (skipped=2)`, exit 0. The two skips are exactly
`test_orderbook_row_is_state_after_message` and `test_inverted_direction_does_not_hold` —
the tests the phase-0 brief names as the load-bearing artifact. Nothing in the exit code or
the final `OK` line distinguishes "alignment verified" from "alignment not run".

Worse, `_raw_files_present()` is all-or-nothing across four hardcoded filenames. Reproduced:
pointing `EDGE_RAW_DIR` at a directory containing only the *deliberately corrupted* AMZN pair
also gives `OK (skipped=2)`. Restoring INTC makes the same corrupted data fail loudly. A
partially-staged or partially-corrupted raw directory therefore reports green.

Combined with finding 1, the phase's designated highest-risk bug is guarded by exactly one
check, and that check disables itself under the default reproduction path.

### 3. MAJOR — `DECISIONS.md` / `DATA_CONTRACT.md` "0/2000 inverted" does not reproduce
`DECISIONS.md:25`, `docs/DATA_CONTRACT.md:75`

The `2000/2000` forward half reproduces exactly. The `0/2000` inverted half is false. Driving
the repo's own `tests/test_alignment.py::_run(ticker, "before")` at seed 0:

| n | INTC forward | INTC inverted | AMZN forward | AMZN inverted |
|---|---|---|---|---|
| 500 | 500/500 | 34/500 | 500/500 | 33/500 |
| 2000 | 2000/2000 | **110/2000** | 2000/2000 | **130/2000** |

I also tested the plausible alternative definition (skip samples where the price is absent
from one of the two rows rather than defaulting to size 0): 110/2000 INTC, 89/1163 AMZN.
No reasonable variant yields zero, and 0.95^2000 ≈ 1e-45 rules out chance. The conclusion is
unaffected (5.5% vs 100% still separates decisively), but a number in the auditable log that
does not reproduce with the repo's own tool defeats the log's purpose.

### 4. MAJOR — `DECISIONS.md` claims a median-mid hard failure that was removed
`DECISIONS.md:81`

The entry states quality.py "hard-fails (`SystemExit`) if crossed-book count != 0 or median
mid falls outside the ticker's expected dollar range." `git show 6692c9e:src/edge/io/quality.py`
line 247 does `raise SystemExit` on the median-mid bound; commit 7ad99b4 ("tighten
data-quality checks") demoted it to a printed `**FAIL**` with exit 0, and no decision entry
supersedes the claim. The crossed-book half is still true; the median-mid half is not.

Reproduced: divided every price column in a `/tmp` copy of the AMZN orderbook by 100 (the
canonical /100-vs-/10000 scaling regression):

```
AMZN: crossed=0 monotonic=True u_shape=True median_mid=$2.2266 (bounds ok=False)
quality_exit=0
```

`make data` passes on a price-scaling regression that the committed record says it cannot.

### 5. MAJOR — `DECISIONS.md` claims a sentinel mask that was deleted
`DECISIONS.md:86`

The entry says a valid-quote mask means "a best-bid/ask pair only counts toward the
crossed-book check and the spread/depth intraday profile if neither side is the LOBSTER
sentinel ... the check is real code now instead of a documented assumption."
`_valid_quote_mask` existed at 6692c9e (lines 42, 79-81, 97, 107) and was removed in 7ad99b4.
Current `crossed_locked_counts` and `build_intraday_profile` consume raw `bid_px_1`/`ask_px_1`
unmasked; `sentinel_row_count` only prints.

Reproduced: injected 1,000 rows with `ask_px_1=9999999999, ask_sz_1=0`:

```
- crossed-book count (`bid_px_1 >= ask_px_1`): 0 (expected 0) -- PASS
- sentinel best-level rows (informational, defensive check): 1000
| 09:30:00-10:00:00 | 17520 | ... | 5706503.924 |   <- mean spread, ticks
quality_exit=0
```

Zero impact on today's numbers (0 sentinel rows in this sample). The defect is that the
committed record describes a defence that is not there.

### 6. MAJOR — `reports/data_quality.md` overstates AMZN's U-shape
`reports/data_quality.md:85`

The report prints `U-shape (open/close activity > midday) confirmed: True` for AMZN with no
qualification. Recomputed 30-minute bins:

```
AMZN [17520, 24960, 24502, 25401, 17374, 18784, 14255, 12441, 20101, 19595, 15215, 26082, 33518]
     open 17520 | close 33518 | bin median 19595 | interior mean 18278.7 | edge mean 23632.8
INTC [84889, 52928, ..., 22798, 39314, 50219, 80991]
     open 84889 (day max) | close 80991 | interior mean 39874.7 | edge mean 57486.2
```

AMZN's opening bin is **below** both the bin median and the interior mean — the open is not
elevated at all; the True is carried by the close plus the 10:00-11:00 bins swept into the
edge quartile. INTC is a genuine bidirectional U. Compounding it, `DECISIONS.md:107` records
the rule being replaced the same day, immediately after AMZN failed the original
"first and last bucket above the median" rule, with the justification that AMZN's open is
"elevated" — contradicted by the numbers above. The change is disclosed in `DECISIONS.md` and
`PLAN.md` says "AMZN's is weaker at the open"; the *report*, read alone, gives none of that.
A parse-validity detector redefined after it returned False on the data under test has
reduced detection power, and the surviving verdict should not be read as "clean U on both".

### 7. MAJOR — `confirm_u_shape` is an edge-heaviness test, and it is print-only
`src/edge/io/quality.py:204`

The predicate is `mean(outer-quartile bins) > mean(interior bins)`. It does not require both
tails to be individually elevated. Probed the real function:

| profile | result |
|---|---|
| flat 13 bins | False |
| monotone decline 13..1 | False |
| inverted-U (midday peak) + large close | False |
| J-shape: flat open, close spike | **True** |
| spike in bin 2 only, flat elsewhere | **True** |
| ramp 1..12 then 20 | **True** |

So it is not trivially-true-for-anything, but it accepts one-sided profiles and a single
early-morning spike — which is exactly what happens for AMZN. `tests/test_quality.py::TestUShape`
has no case for the one-sided scenario. Separately, `u_shape` is not in `hard_failures`, so
even a False verdict passes `make data`: PLAN.md's "if the U-shape isn't there, the parse is
wrong" is not enforced anywhere.

### 8. MAJOR — `test_inverted_direction_does_not_hold` is near-vacuous
`tests/test_alignment.py:132`

The assertion is `assertLess(n_holds, n_checked)` with `n_checked == 500`, so it passes for
any `n_holds` in [0, 499] — including 499/500 supporting the inverted convention. It fails
only on a perfect 500/500, which cannot occur unless every message's effect is idempotent.

Demonstrated on genuinely misaligned data (the +1-shifted AMZN orderbook): forward drops to
33/500 and correctly FAILS, while the inverted test still PASSES at 10/500. The docstring and
`DATA_CONTRACT.md` present this as a second independent line of defence; a reviewer counting
two checks is counting one. `assertLess(n_holds, 0.25 * n_checked)` would encode the intent.

### 9. MAJOR — `tests/test_quality.py` tests no escalation path
`tests/test_quality.py:1`

The 16 tests import only pure primitives (`crossed_locked_counts`, `check_monotonic_ts`,
`top_k_gaps`, `median_mid_dollars`, `build_intraday_profile`, `confirm_u_shape`,
`sentinel_row_count`, `gaps_over_threshold`, `ns_to_hhmmss`). Untested: `main`,
`build_ticker_report`, the `hard_failures` assembly, `count_lines`, `_event_count_table`'s
MISMATCH path, `_gap_table`, `_intraday_table`, `write_report`. The module's load-bearing
claim — "Hard invariants (non-zero exit, fails `make data`)" — has no test. This is precisely
what allowed findings 4 and 5 (the median-mid demotion and the mask deletion) to land in a
commit titled "tighten data-quality checks" with the suite green.

### 10. MAJOR — the alignment invariant is blind to level permutation
`tests/test_alignment.py:46` (`_level_size`)

`_level_size` scans all ten levels for an exact price match, so depth ordering is invisible
to it. Reproduced: reversed levels 3..10 on both sides of the AMZN book and reran the test —
**500/500 PASS**. Every depth-indexed feature downstream (queue imbalance, microprice, L1
depth, weighted mid) would be computed from the wrong level while the phase-0 invariant stays
green. Levels 1-2 are covered by the 2-level toy fixture in `tests/test_lobster.py`; a
permutation among levels 3..10 of the real files is caught by nothing in the suite. The
actual parse *is* correct (two agents independently confirmed ask prices strictly ascending
and bid prices strictly descending across all levels on all 893,788 rows), but that
verification lives in scratch scripts, not in the repo.

### 11. MAJOR — `build_event_frame` has no value assertion
`tests/test_lobster.py:95`

`TestBuildEventFrame.test_schema_and_join` asserts column names/order and row count only.
There is not one assertion that a value in the frame matches the source table.
`tests/test_alignment.py` exercises `read_message_file`/`read_orderbook_file`, never
`build_event_frame` — so the invariant is established on intermediate tables and assumed to
survive the reorder-and-write step that produces the artifact every later phase reads. The
current implementation is name-keyed and therefore safe; that is implementation luck, not
coverage.

### 12. MINOR — "archive blocked" in the committed record is false
`DECISIONS.md:26`, `docs/DATA_CONTRACT.md:67-68`, `tests/test_alignment.py:9-11`

The Wayback snapshot loaded on the first try with no proxy or retry (see the quotation at the
top of this report). The live-site half of the claim is accurate — `lobsterdata.com/info/DataStructure.php`
serves a 457-byte SPA shell and `data.lobsterdata.com` does not resolve — but "no cached
mirror reachable either" is not. Downgraded from the reporting adversary's MAJOR because the
conclusion it supported is now independently confirmed *by that very source*, and because I
cannot rule out that the fetch used in phase 0 was sandboxed differently from plain
curl (see "could not check"). The defect is recording a tool limitation as a property of the
environment without the command.

### 13. MINOR — `_parse_ts_ns` drops the sign on negative seconds
`src/edge/io/lobster.py:28`

`s.partition(".")` then `int(sec_str) * NS_PER_SEC + int(frac_str)` gives `-1.5` →
`-500000000` ns instead of `-1500000000`, and `-0.5` → `+500000000`, a sign flip. Unreachable
in LOBSTER data (zero negative times in either file, confirmed) but this is the project's
only timestamp path and Phase 4 may introduce signed deltas.

### 14. MINOR — `discover_pairs` silently overwrites on a duplicate ticker-day
`src/edge/io/lobster.py:144`

Keyed on `(ticker, date)` only, while the output is `{TICKER}_{DATE}.parquet`. Two message
files for the same ticker-day with different `start`/`end` windows both get discovered and the
second silently overwrites the first, exit 0. Harmless today; silent data loss the moment a
second intraday window or a re-download with a different window appears.

### 15. MINOR — no scripted path to obtain the raw data
`Makefile:4`

`RAW_DIR ?= data/raw/lobster` with `data/` gitignored and no `fetch` target. A fresh clone has
no scripted way to get the CSVs; the Hugging Face mirror is mentioned only in `DECISIONS.md`
prose. "`make data` clean from a fresh checkout" is true only after the operator sources the
raw files by hand, and nothing enforces or automates that. Both this session and the
the verification worked around it by symlinking from the existing checkout.

### 16. MINOR — duplicate raw CSVs under `data/raw/`
`data/raw/`

`data/raw/*.csv` and `data/raw/lobster/*.csv` are byte-identical duplicates (~258 MB).
`discover_pairs` uses non-recursive `os.listdir`, so `RAW_DIR=data/raw/lobster` is unambiguous
today, but `RAW_DIR=data/raw` would silently process the stray top-level copies with no signal
in the report. Not deleted (out of scope for a read-only gate).

### 17. MINOR — intraday profile clips out-of-session timestamps into the edge bins
`src/edge/io/quality.py:177`

`np.clip` folds any timestamp outside 09:30-16:00 into the first or last bin — the direction
that makes `confirm_u_shape` *more* likely to return True. Out-of-session timestamps (wrong
epoch, wrong session offset, pre-open auction rows) are a canonical parse error, so the
detector is strengthened by the class of bug it exists to detect. Zero clipped rows on this
data (AMZN spans 09:30:00.017-15:59:59.959, INTC 09:30:00.006-15:59:59.948), and
`tests/test_quality.py` enshrines the clipping as intended, so no committed number is affected.

## Could not check

- **Provenance of the raw CSVs.** No published per-file checksum is reachable. Every check —
  the repo's, the six agents', and mine — is internal consistency between two files downloaded
  together. A defect uniform across both files, or an orderbook file re-derived from the
  message file, is invisible to all of them. The `docs/DATA_CONTRACT.md` event-count table was
  derived from these same files, so that cross-check is circular by construction. Closing this
  needs an independent NASDAQ ITCH reconstruction, which does not exist here.
- **Whether the phase-0 work could have reached web.archive.org.** I know plain
  curl reaches it from this machine today. If its fetch tool was sandboxed differently,
  "archive blocked" was true of the tool and false of the environment. This is why finding 12
  is MINOR rather than MAJOR.
- **`orderflow-lm`'s `SPEC.md`**, cited as the independent convention reference, and the
  "90.3% best-bid disagreement on 10-level AMZN" figure from its `book_source_compare`. The
  repository is outside this working directory and was not read here. Moot for the conclusion
  now that the primary source says the same thing.
- **Generalisation beyond 2012-06-21 INTC/AMZN at 10 levels.** Every zero in the report
  (sentinels, halts, type-6/7, locked, crossed, out-of-session rows) is a property of this one
  sample. `_level_size`'s first-match assumption is untested against sentinel-padded rows
  because no such rows exist here.
- **Phase-1 code.** `src/edge/features/`, `tests/test_book.py`, `tests/test_clocks.py`,
  `tests/test_normalize.py`, `tests/test_windows.py`, `tests/toybook.py`, `docs/INTERFACE.md`
  are uncommitted and explicitly out of scope for this gate. Note that `make test` in the
  working tree runs 68 tests (green); the 28-test figure is the committed-only clone.
- **Items 2-10 of the standard order of suspicion** (lookahead, scaler fit, label overlap, R2
  vs mean, base rate, deadband, dev slice, trial count, pooled laundering) have no phase-0
  surface: no `.fit(`, no `shift(`/`rolling(`, no metric code under `src/edge/io/`, no labels,
  folds or filled `RESULTS.md` rows. Recorded as not-applicable, not as passing.

## What would change my mind

Any one of these flips this gate to KILLED:

1. **A published LOBSTER checksum, or an independent ITCH reconstruction of INTC/AMZN
   2012-06-21, that disagrees with these CSVs.** That is the one failure mode no check here
   can see, and it would invalidate the whole phase rather than just its documentation.
2. **Evidence that the level ordering in the parsed frame is wrong.** Finding 10 shows the
   repo's own invariant cannot detect it. Today ask prices are strictly ascending and bid
   prices strictly descending on all 893,788 rows, so I am confident it is right — but that
   check lives outside the repo, and if it ever fails, every Phase-1 depth feature is wrong.
3. **A reproduction of the committed `0/2000` inverted-hold figure** by any defensible
   construction. I tried two and got 110/2000 and 89/1163. A third that yields zero would
   demote finding 3 to a wording issue.
4. **A Phase-1 number computed on `data/frames/*.parquet` that a re-derivation from raw
   disagrees with.** Findings 1, 2 and 11 mean nothing in `make data` or the default `make test`
   would catch a mis-joined frame; a downstream disagreement would promote them to blockers.
